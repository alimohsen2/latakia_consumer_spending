# نظام أتمتة دائرة الإنفاق الاستهلاكي: مديرية مالية اللاذقية

تطبيق Flutter Web بواجهة عربية من اليمين إلى اليسار. هذه النسخة **تجريبية** تحفظ بياناتها في المتصفح (SharedPreferences)، وجاهزة للانتقال إلى خلفية وSQL Server (انظر `docs/API.md` و`docs/schema.sql`).

## التشغيل
```bash
flutter create . --platforms=web --project-name latakia_consumer_spending   # يولّد مجلد web فقط
flutter pub get
flutter analyze            # أرسل لي أي أخطاء تظهر
flutter run -d chrome
flutter build web --release
```

> **إذا كان مسار المشروع يحتوي أحرفاً عربية** (مثل `Desktop/إنفاق استهلاكي/`): تفشل أداة Flutter في تقليص الأيقونات وتُظهر `Failed to open output file ... CupertinoIcons.ttf`. الحل: أضف `--no-tree-shake-icons`:
> ```bash
> flutter run -d chrome --no-tree-shake-icons
> flutter build web --release --no-tree-shake-icons
> ```
> أو انقل المشروع إلى مسار لاتيني مثل `C:\Projects\latakia_consumer_spending` لتعمل الأوامر العادية. هذه مشكلة في أداة Flutter نفسها ولا تؤثر على الكود.
الحسابات التجريبية عند التهيئة الأولى (كلمة المرور `123456`): `admin` · `head` · `info_head` · `dept` · `field_head` · `office_head` · `archive_head` · `field1` · `office1` · `archive1`. بيانات الدخول التجريبية لا تعني أن هذه الحسابات موجودة في كل نسخة؛ الحسابات المحلية قد تختلف بعد إدارتها.

## التصميم
- لغة تصميم أبل: عناوين كبيرة (Large Title)، خلفية واجهة **بيضاء**، بطاقات بيضاء بحواف مستمرة (squircle) وظل ناعم، فواصل رفيعة، حقول بحث رمادية مستديرة، أزرار ملوّنة (Filled) وثانوية خفيفة (Tinted)، مفاتيح تبويب منزلقة (Segmented Control)، وحقول تحديد دائرية.
- **الوضع الداكن:** مبدّل في الشريط العلوي (أيقونة القمر/الشمس)، وفي شاشة الدخول، وفي «الإعدادات ← المظهر». يُطبَّق فوراً على كل الشاشات ويُحفظ في الإعدادات (`darkMode`) فيبقى بعد إعادة التشغيل. الألوان كلها من لوحة واحدة (`AppPalette` فاتح/داكن) عبر `context.p`، فأي إضافة جديدة ترث الوضعين تلقائياً.
- الأيقونات: مجموعة CupertinoIcons (حزمة cupertino_icons). أيقونات SF Symbols وخط SF الخاصان بأبل غير مرخّصين للاستخدام خارج منصاتها، لذلك استُخدم خط IBM Plex Sans Arabic وهو الأقرب في الشكل. يمكن تغييره من `lib/core/theme.dart`.
- الهوية الحالية: **أبيض فخم + أخضر مزرق (Teal) `#17574E`**. اللون مستخرج من هوية الدائرة ويُستخدم لوناً للثيم: خلفية **القائمة الجانبية**، والأزرار الأساسية، والعناصر النشطة، وشعار شاشة الدخول. الأزرار الثانوية بخلفية Teal خفيفة (`#EAF3F1`)، والحدود والحقول بمسحة خفيفة من Teal، مع لمسة ذهبية هادئة (`kGold`) للتفاصيل. أيقونات القائمة الجانبية **ملوّنة** لكل قسم (ذهبي، مرجاني، سماوي، نعناعي، وردي، بنفسجي...) على خلفية Teal بنصوص بيضاء.
- **الشعارات:** شعارا **وزارة المالية** و**مديرية مالية اللاذقية** (`assets/logos/mof_logo.png` و`assets/logos/dept_logo.png`) يظهران في **شاشة الدخول** أعلى بطاقة الدخول داخل لوحة بيضاء مستديرة (`BrandLogos` في `lib/widgets/brand.dart`) ليبقيا واضحين في الوضعين الفاتح والداكن. أُزيلا من رأس لوحة التحكم بطلب من الإدارة.
- **شاشة الدخول:** خلفية بيضاء بتدرّج Teal خفيف وهالتين لونيتين، الشعاران أعلى الشاشة (ارتفاع 44px) على لوحة بيضاء مستديرة، ثم عنوان الدائرة واسم المديرية، فبطاقة دخول بلا نصوص حشو (حُذفت «الجمهورية العربية السورية» و«نظام أتمتة المحاضر والمكلفين» و«أدخل بيانات حسابك للمتابعة» وقائمة الحسابات الطويلة، واستُبدلت بسطر «تجريبي: admin / 123456»). حقل كلمة المرور بزر إظهار/إخفاء، وأنيميشن دخول متدرّج (تلاشٍ + انزلاق + تكبير خفيف) يحترم إعداد تقليل الحركة في النظام.
- **لوحة التحكم:** رأس بعنوان اللوحة وتاريخ اليوم وأزرار العمل (بلا شعارات وبلا عبارة تعريفية)، ثم قسم **«إحصائيات المكلفين»** بأربع بطاقات عصرية متحرّكة (إجمالي المكلفين، الفعالون، المتوقفون، المتوقفون مؤقتاً) بعدّاد تصاعدي وتلاشٍ وانزلاق متدرّج، ثم قسم **«المبيعات والتحليل»** بأربع بطاقات مؤشرات (إجمالي المبيعات، مبيعات الشهر الحالي، المتوسط الشهري، انخفاض المبيعات) ورسم أعمدة لحركة المبيعات الشهرية. أُزيل قسم «آخر المحاضر» نهائياً. البطاقات تتجاوب 4/2/1 أعمدة بلا فيض على 420px.
- **قائمة المكلفين:** هيرو بعنوان الصفحة وأزرار (استيراد Excel/تصدير/إضافة مكلف)، وأربع بطاقات إحصاء (إجمالي المكلفين، الفعالون، المتوقفون، انخفاض المبيعات)، وبطاقة بحث وتصفية (بحث حر + نوع البحث + الفئة + الحالة + فلاتر محفوظة)، ثم جدول عريض على الشاشات الكبيرة وبطاقات مدمجة على الضيقة، وتذييل ترقيم صفحات. التصميم متجاوب بلا فيض على عرض 420px.
- **صفحة المكلف:** بطاقة هوية كبيرة (اسم، حالة، رقم ضريبي، فئة، عنوان) مع زر **رجوع** أعلى الصفحة، وأزرار العمل (محضر جديد/تعديل/تغيير الحالة)، ثم بطاقة **أضبارة المكلف** المستقلة أسفلها، وأخيراً تبويبات المحاضر والمبيعات والبيانات الشهرية وسجل الحالة.

## ما يتضمنه
- **الأدوار:** مدير النظام، مدير المالية، رئيس قسم الواردات، رئيس قسم المعلوماتية، رئيس دائرة الإنفاق الإستهلاكي، ورؤساء الشعب الميدانية والمكتبية والأرشيف، إضافة إلى المراقب والموظف. الصلاحيات الافتراضية في مصفوفة يعدّلها المدير (`/permissions`)؛ رئيس قسم المعلوماتية يبدأ بصلاحيات العرض فقط.
- **المكلفون:** بحث بالاسم والرقم الضريبي (يتجاهل التشكيل والهمزات)، فلاتر محفوظة، تحديد جماعي، استيراد من Excel بلصق الصفوف، تصدير، سجل تغيّر الحالة.
- **أضبارة المكلف:** صفحة مستقلة لكل مكلف (`/taxpayers/{id}/file`) لصور الأوراق الورقية داخل أضبارته (سجل تجاري، هوية، إجازة، عقد إيجار...) مع معرض مصغّرات، معاينة، تنزيل، وإضافة/حذف. يديرها من يملك تعديل المكلفين أو شعبة الأرشيف. راجع `docs/TAXPAYER_FILE.md`.
- **المحاضر:** رقم مطبوع مسبقاً أو تلقائي (من الإعدادات) مع التحقق من التكرار والدفاتر، حفظ تلقائي للمسودات، مسار اعتماد (مستخدم ← رئيس الشعبة المختصة ← رئيس دائرة الإنفاق الإستهلاكي)، طباعة PDF بخط عربي وQR، قفل بعد الطباعة، إلغاء بسبب مكتوب (لا حذف)، محضر بديل.
- **السجلات:** سجل المخالفات وسجل المتابعة، والبيانات الشهرية وتقرير غير المقدمين (يستثني المتوقفين).
- **إدارة المستخدمين:** بحث وتصفية بحسب الدور والشعبة والحالة، تسلسل المسؤول المباشر، كلمة مرور مؤقتة تُغيّر عند أول دخول، تغيير ذاتي لكلمة المرور، سجل إنشاء وتعطيل وإعادة تفعيل وإغلاق نهائي. الإغلاق يتطلب سبباً وتأكيداً، ويحفظ سجلات الحساب؛ لا يوجد حذف فعلي للحسابات.
- **المبيعات:** يومي وشهري وسنوي لكل مكلف من واجهة API (تجريبية الآن)، وكشف الانخفاض بثلاث عتبات، وتنبيهات يحدد المدير مستلميها.
- **الأرشيف والمرفقات:** فهرس بحث متقدم للمحاضر المقفلة/المعتمدة/الملغاة، تسجيل مرجع الملف والصندوق، مرفقات (صور المخالفة، إشعارات، PDF) بمعاينة وتنزيل، طباعة بطاقة أرشيف بـ QR. راجع `docs/ARCHIVE.md`.
- **المفتش الميداني:** تتبع GPS أثناء الجولة الميدانية من شاشة «المفتش الميداني» (`/field/monitor`): بدء/إنهاء الجولة، وعرض الموقع والإحداثيات والدقة، وإرسال الموقع إلى الخادم (REST). راجع `docs/FIELD_APP.md`.
- **منع التلاعب:** سجل عمليات متسلسل بالبصمات، بصمة لكل محضر مقفل، توقيع QR، دفاتر أرقام وتسويات، فحص سلامة، صفحة تحقق (`/verify`).

## حدود هذه النسخة (بصراحة)
1. الكود يُحلَّل وينبني بنجاح (`flutter analyze` بلا أخطاء أو تحذيرات، و`flutter build web` ناجح). اختُبرت الواجهة الجديدة في المتصفح (الدخول، اللوحة، المكلفون، صفحة المكلف) بلا أخطاء كونسول. اجتازت اختبارات إدارة الحسابات، بينما يفشل اختبار `flutter test` الخاص برسم لوحة التحكم حالياً لعدم العثور على نص «لوحة التحكم». راجع خطوات الاختبار في `docs/ARCHIVE.md` و`docs/FIELD_APP.md`.
2. التخزين في المتصفح لا يمنع من يفتح أدوات المطوّر من تعديل بياناته. الحماية الحقيقية تتحقق بنقل القفل والتوقيع والسلسلة إلى الخلفية.
3. مفتاح توقيع QR وتجزئة كلمات المرور هنا للتجربة فقط.
4. المرفقات والمسودات الميدانية وصور أضبارة المكلفين محفوظة محلياً (SharedPreferences) وبحد 1.5 ميغابايت للملف. مسح بيانات المتصفح يحذفها. في الإنتاج تُرفع للخادم.
5. مزامنة الميدان: الوضع الافتراضي محلي (يُنشئ المحضر داخل النظام). الوضع الخادمي يرسل `POST /field/sync` ويتطلب خلفية تحقق الترقيم والصلاحيات. لا مزامنة خلفية تلقائية ولا حل تعارضات. تطبيق الموبايل الأصلي يحتاج `flutter create --platforms=android,ios` وإضافة الكاميرا/الموقع (انظر `docs/FIELD_APP.md`).
6. تحميل خط Tajawal يتم من الإنترنت عند أول طباعة. للعمل بلا إنترنت ضمّن ملف الخط في assets.
7. لا تنسَ `flutter pub get` بعد إضافة `file_picker` و`http`.
